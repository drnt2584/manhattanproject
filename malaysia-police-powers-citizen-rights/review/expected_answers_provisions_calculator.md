# Expected answers: Provisions tab and Calculator tab

Companion to `QA_report_2026-10-13.md`. This sets out what a complete reviewer entry looks like on each row, so the reviewer can redo the two tabs against a fixed standard.

## Provisions tab

### What the columns ask

The column being reviewed is "Statutory text (latest version)", with "PDF page" beside it. The Read me says: "the statutory text cited by each claim is shown beside it, with the PDF page of the official reprint. OCR text can contain recognition errors: check against the PDF where it matters." So each row asks three questions, and the Reviewer notes must answer all three:

1. **Transcription.** Does the text in the cell match the reprint, word for word, at the page stated? List any OCR errors found (the pack has several: "Jaw" for "law", "itssued", "PART!", "immediate! y", "(IA)" for "(1A)", "]Place", "indirecHy", "ifhe", "m Malaysia"). None of these change meaning, so the verdict can stay Approve, but the note must list them so they can be cleaned before the text is shown to anyone.
2. **Page.** Is the page reference right? If wrong, give the right one. State which convention the pack uses (printed page number, or PDF page index); the pack is inconsistent (the Federal Constitution rows use the PDF index, the CPC rows use the printed number).
3. **Currency.** Is this the latest version? Cross-check against the Sources & currency tab: if an amending Act after the reprint date is listed for that instrument, state whether it touches this section. If it does, the verdict is Amend and the note says what changed and from when.

A note that says only "Accurate statutory text verified against official reprint (p.X)" answers question 1 by assertion and questions 2 and 3 not at all.

## Calculator tab

### What the column asks

"Reviewer answer / notes" is a yes/no confirmation for the six parameter rows and a substantive answer for the four open questions. The app will compute remand timelines from these values, so every answer needs: the result (Confirmed / Not confirmed / Unsettled), the section relied on, any caveat that affects the computation, and no citation markers that point to nothing. The replies as submitted contain bracketed references [1] to [7] with no reference list; those must go or a list must be added.

|---|---|---|
| 24-hour production | 24 hours; necessary journey time not counted | **Confirmed.** FC Art 5(4) ("within twenty-four hours (excluding the time of any necessary journey)"); CPC s.28(3) ("exclusive of the time necessary for the journey from the place of arrest to the Magistrate"). Caveat for the model: only time genuinely necessary for the journey is excluded; the clock runs from the moment of arrest (CPC s.15(1)). |

| OPEN QUESTION: counting from arrest or from the remand order | — | Two separate answers. (a) The 24-hour clock runs from the arrest (CPC s.15(1), s.28(3); FC Art 5(4)). Confirmed. Time already spent in custody is not deducted by the statute; s.117(3)-(4) only require it to be disclosed and "taken into consideration" by the Magistrate when fixing the period. Modelling decision: show the pre-remand custody and the remand period as two segments; do not net one off the other unless the order itself does. |
